# Кроул сети

Каталог собран из среза MenuStat 2018: все 25 366 позиций помечены `stale`.
Кроул — единственный способ это исправить и **единственное место конвейера,
которое пишет в `items` поверх того, что уже видят люди**. Отсюда все правила
ниже: они не про аккуратность, а про то, чтобы не испортить работающее.

## Порядок

```bash
# 1. Разведка: чем сеть отдаёт данные
python3 backend/scripts/probe_chain.py --menu https://www.wendys.com/menu

# 2. Кроул без записи — смотрим, что он собрался сделать
python3 backend/scripts/crawl_chain.py wendys --menu https://www.wendys.com/menu \
        --cache backend/data/crawls/wendys-live.json

# 3. Если план верен — записываем
python3 backend/scripts/crawl_chain.py wendys --apply

# 4. Дальше как обычно: разделы → пак → Storage
./backend/scripts/publish_pack.sh N
```

`--cache` обязателен на первом прогоне: обход сотни страниц с паузой в пять
секунд идёт минуты, и повторять его ради правки отчёта незачем. Второй запуск
с тем же `--cache` не ходит в сеть вовсе.

Адрес меню запоминается в `chains.source_url` при первом `--apply`, дальше
хватает slug.

## Что кроул делает и чего не делает

| | |
|---|---|
| Обновляет числа у **сматченных** позиций | ✅ новая версия в `items` |
| Заводит новые позиции сети | ❌ у новинки нет ни категории, ни раздела, ни варианта |
| Закрывает то, чего не нашёл | ❌ это `check_menu_presence.py`, у него своя таблица |
| Трогает название, категорию, раздел, пометки | ❌ несёт из закрываемой строки |
| Переживает `overrides` | ✅ правки лежат отдельно и накладываются при экспорте |

**Ненайденное не закрывается.** «Блюда нет в меню» и «наш обход не дошёл до
его страницы» для кода неразличимы, а последствия разные: первое — факт,
второе — наша поломка. Число ненайденных идёт в отчёт и в дифф-проверку.

**Версия, а не перезапись.** Старая строка получает `valid_to = now()`, рядом
встаёт новая с `source` домена сети, `stale = false` и сегодняшней
`observed_at`. У позиции остаётся история, `items_export` берёт текущую.

## Четыре запрета, каждый оплачен ошибкой

1. **Неполная этикетка не применяется.** Сеть отдала калории без макросов —
   позиция не обновляется вовсе. Свежие калории рядом с макросами 2018 года
   дают строку, которая не сходится сама с собой, а проверка Атуотера —
   единственное, чем мы ловим съехавшую колонку.
2. **Битая позиция не затирает верную.** Не сошлась по Атуотеру — старые
   числа остаются, проблема идёт в отчёт.
3. **Сломанная доля гасится, позиция едет.** Сахар больше углеводов — гасим
   сахар, остальное применяем (`validate.strip_broken_label`).
4. **Держим на дифф-проверке.** Пропало >20% или изменилось >30% — это
   редизайн сайта, а не новое меню. `crawls.status='held'`, с `--apply`
   ничего не пишется, релиз не собирать.

## Матчинг имён — `plateful_data/matching.py`

MenuStat писал «Chick Fil a Nuggets», сайт пишет «Chick-fil-A® Nuggets».
Правило одно на сверку и кроул, менять только там.

* **Размер и число совпадают точно.** «4 Nuggets» и «8 Nuggets» отличаются
  вдвое, а по строке почти неразличимы.
* **Единица счёта — не размер.** `ct`, `count`, `pc` выбрасываются: блюдо
  отличает число, а не слово при нём.
* **Запись каталога занимается один раз.** Иначе одна строка попадала в
  отчёт дважды с разными числами.
* **Сходство считается по всем кандидатам**, а не только по прошедшим порог,
  иначе у непойманной позиции в отчёте всегда ноль и «промахнулись на
  волосок» неотличимо от «такого блюда нет».

Порог `MATCH_THRESHOLD = 0.82`. Ниже — в отчёт человеку, не в правки:
выдумать соответствие хуже, чем признать, что позиция не сматчилась.

## Чтение страницы — `adapters/site.py`

Лесенка из трёх извлекателей, каждый добавляет недостающее: JSON-LD (сеть
держит его ради Google, потому он аккуратный) → JSON для гидратации фронта
(`__NEXT_DATA__`, `data-wp-context`) → Open Graph (только имя и снимок, зато
почти везде). Сеть, у которой сработал любой, подключается **без своего
кода** — нужен только адрес меню.

Обход двухуровневый: страница с этикеткой — блюдо, страница без этикетки, но
со ссылками внутрь меню — раздел, спускаемся. Глубже не ходим: третий уровень
у сетей — это аллергены, кастомизация и карточки заведений.

Потолки правдоподобия обязательны: во вшитом JSON лежит всё состояние
страницы, и «calories» там встречается не только у еды — разведка по Taco Bell
принесла блюдо на 6 700 205 ккал.

## Вежливость — не опция

`adapters/base.py`: пауза 5 секунд (Chick-fil-A отвечает 429 уже на третьем
десятке при паузе в секунду и держит в пенальти минутами), честный User-Agent
с адресом проекта, только домен сети, никакого обхода CAPTCHA и логинов.
За Akamai (McDonald's, Panera) Python не проходит по отпечатку TLS — там
`--browser`, то есть curl с браузерными заголовками.

Пищевые факты не защищены копирайтом (Feist), публиковать их сети обязаны
(21 CFR 101.11) — но это не повод вести себя как бот-пылесос.

## Проверять результат, а не процесс

Тесты кроула не ходят в сеть: `backend/tests/test_crawl.py` кормит решение
готовыми позициями. Сайт меняется, и тест, который в него ходит, становится
то зелёным, то красным без единой правки в коде.

После живого прогона смотреть глазами именно это:

```sql
select ext_key, name, kcal, source, observed_at, stale
from items where chain_id = (select id from chains where slug = 'chick-fil-a')
  and valid_to is null and not stale;

select * from crawls order by started_at desc limit 5;
```
