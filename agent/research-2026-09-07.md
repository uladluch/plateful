# Ресёрч: данные и технологии

Проверено 2026-09-07 живыми запросами и скачиванием датасетов.
**Этот документ отменяет ключевые выводы `data-source.md`.**

## 1. USDA не подходит как источник. Проверено

### Таблица покрытия в `data-source.md` измеряет шум, а не покрытие

`totalHits` у USDA — это OR-совпадение по словам запроса, а не число позиций сети.
Доказательство из живой выдачи:

| Запрос | totalHits |
|---|---:|
| `Chick-fil-A` (из `data-source.md`) | 7 696 |
| `Chick-fil-A Chicken Sandwich` | **26 022** |

Добавление слов **увеличило** число хитов втрое. При AND-семантике так не бывает.
Значит «Olive Garden — 29 909» считает записи со словом *olive* (оливковое масло)
и *garden* (garden salad), а не позиции меню сети.

### В выдаче нет позиций меню

Запрос `Chick-fil-A Chicken Sandwich`, первые 4 результата:

```
CHICK-FIL-A SAUCE, 16 FL OZ        brandOwner: T. Marzetti Company
CHICK-FIL-A SAUCE, 24 FL OZ        brandOwner: T. Marzetti Company
CHICKEN SANDWICH, CHICKEN          brandOwner: Foodbrands America Inc.
CHICK LICIOUS BREADED NUGGETS      brandOwner: Hall's Specialty Food Prod
```

Ни одной позиции меню Chick-fil-A. Первые две — бутилированный соус в рознице,
`packageWeight: 16 fl oz`, произведён сторонней компанией по лицензии.

Причина системная: `dataType=Branded` — это Global Branded Food Products Database,
каталог **упакованных товаров с UPC-штрихкодом**. У блюда в ресторане нет UPC,
поэтому его там принципиально нет. Независимая проверка GBFPD против сайтов
брендов дала совпадение 45%.

### DEMO_KEY непригоден даже для разработки

Заголовок ответа: `x-ratelimit-limit: 10` — **10 запросов в час**, не 30.
Упёрлись после второго запроса. Свой ключ (1000/час) обязателен для любой работы
с USDA — но с учётом пунктов выше идти туда незачем.

## 2. Рабочий источник: MenuStat (CC0)

`menustat.org` больше не резолвится, сайт мёртв. Данные живы на зеркале
Harvard Dataverse: **doi:10.7910/DVN/K4NYTR**, лицензия **CC0 1.0** —
общественное достояние, коммерческое использование без атрибуции.

Годы: 2008, 2010, 2012–2015, 2017, 2018. Источник — NYC DOHMH, собирали с
опубликованных сетями данных по федеральному правилу menu labeling.

### Что внутри 2018 года (скачано и посчитано)

| Метрика | Значение |
|---|---:|
| Строк в файле | 71 172 |
| Из них combo-перестановок (`Accompanying Item`) | 41 052 |
| После снятия перестановок | 30 120 |
| **Чистый каталог: уник. позиция + полные ккал/Б/У/Ж** | **25 838** |
| Сетей | **96** |
| Размер бандла | **2.13 MB raw / 0.37 MB gzip** |

Заполненность: калории 94.1%, белки 91.9%, жиры 93.1%, углеводы 92.3%.
Все четыре макроса сразу — у 90.1% строк.

Колонки — ровно те, что нужны продукту: `Restaurant`, `Item_Name`,
`Food_Category`, `Serving_Size_household`, `Calories`, `Protein`,
`Carbohydrates`, `Total_Fat` (+ натрий, сахар, клетчатка, транс-жиры).

### Свежесть — главный риск, измерен на двух позициях

| Позиция | MenuStat 2018 | Сейчас (сайт сети) | Дрейф |
|---|---|---|---|
| Big Mac | 540 kcal, P25 C46 F28 | 580 kcal, P25 C45 F34 | ккал +7%, жир **+21%** |
| Taco Bell Crunchy Taco | 170 kcal, P8 C13 F9 | 170 kcal | совпадает |

Калории дрейфуют умеренно, отдельные макросы — заметно. Оговорка
«values as a guide, not a guarantee» в `description.txt` это покрывает,
но перед релизом нужен аудит: сверить топ-20 позиций каждой из 8 ключевых
сетей с их текущими опубликованными данными и поправить вручную.
Это ~160 позиций — работа на один день, и она закрывает 80% реальных запросов.

## 4. Вывод по архитектуре: сеть не нужна вообще

Каталог 0.37 MB в gzip кладётся в бандл приложения. Следствия:

- **API-ключа нет** → нечего прятать → нет причины для прокси
- **Сетевых запросов нет** → нет rate limit, нет офлайн-режима как отдельной фичи
- Поиск по 25 838 позициям в памяти — единицы миллисекунд, без индексов
- «Works offline» из `description.txt` становится буквальной правдой, а не кэшем

### Нужен ли Supabase — нет, для v1 не нужен

Бэкенд оправдан только тремя вещами, и ни одна не блокирует релиз:

1. **Обновление данных без релиза в App Store.** Датасет протухает — это реальная
   потребность. Но решается статическим JSON-файлом на любом CDN или в
   Supabase Storage; полноценная база и RLS не нужны.
2. **Аналитика поисковых запросов** — какие сети и блюда ищут, чтобы знать,
   что дополнять. Полезно, но это задача аналитики, не бэкенда.
3. **Правки от пользователей** («здесь неверные калории»). Фича далёкая.

Рекомендация: v1 полностью офлайн, без Supabase. Слой данных спрятать за один
протокол (`MenuRepository`), чтобы позже подменить бандл на удалённый data pack
без переписывания UI. Покупку проверяет StoreKit 2 на устройстве — сервер
для разовой непотребляемой покупки не нужен.

## 5. Технологии

### Deployment target — исправить

Сейчас `IPHONEOS_DEPLOYMENT_TARGET = 26.5`. Это точечный релиз: отсекает всех
на 26.0–26.4 и весь iOS 18 (~14–18% устройств). iOS 26 в целом — около 79%
заходов в App Store (июнь 2026), iOS 18 как минимум даёт **88.3%** охвата.

Приложению не нужен ни один API из iOS 26. Ставить **iOS 18.0**.

`SWIFT_VERSION = 5.0` при Xcode 26 — переключить на Swift 6 с строгой
конкурентностью, пока кода почти нет и миграция бесплатна.

### Хранение

- **Каталог** — не SwiftData. Это read-only справочник, который едет в бандле.
  Загрузить один раз в память из бинарного/JSON-ресурса. 25 838 записей ≈ 2 MB
  в памяти; линейный поиск быстрее, чем накладные расходы на БД.
- **SQLite + FTS5** — запасной вариант, если каталог вырастет на порядок.
  FTS5 включён в системном SQLite (`ENABLE_FTS5` подтверждён), GRDB.swift
  даёт типизированный доступ. На текущем объёме это лишняя зависимость.
- **SwiftData** — только для того, что пишет пользователь: сохранённые заказы
  и история просмотров. Десятки записей, идеальная задача для SwiftData.

### Покупка

StoreKit 2, один non-consumable. `Transaction.currentEntitlements` для проверки,
`.storeKit` конфиг для тестов в симуляторе. Сервер верификации не нужен.
В `description.txt` обещано «No subscription» — держать буквально.

### Что это меняет в мета-данных

Всё остаётся в силе, кроме одного абзаца в `description.txt`:
блок «WHERE THE NUMBERS COME FROM» ссылается на USDA FoodData Central.
Его надо переписать на MenuStat / NYC DOHMH. Дисклеймеры про порции,
неаффилированность и «не медицинский совет» остаются как есть.
