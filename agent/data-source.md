# Источник данных — MenuStat

Перепроверено 2026-09-07. **Этот документ отменяет предыдущую версию, где
источником назывался USDA FoodData Central.** USDA не подходит, разбор ошибки
в конце файла.

---

## Что берём

**MenuStat** — данные о меню сетей США, собранные NYC DOHMH по федеральному
правилу menu labeling. Оригинальный сайт menustat.org мёртв, данные живут на
зеркале Harvard Dataverse.

```
DOI      doi:10.7910/DVN/K4NYTR
Лицензия CC0 1.0 — общественное достояние, коммерческое использование
         без атрибуции и без ограничений
```

Метаданные (проверено, HTTP 200):
```
GET https://dataverse.harvard.edu/api/datasets/:persistentId/?persistentId=doi:10.7910/DVN/K4NYTR
```

Скачивание файла по id (проверено, HTTP 200, 27.3 МБ):
```
GET https://dataverse.harvard.edu/api/access/datafile/6191167
```

Годы и file id: 2008 `6191166`, 2010 `6191164`, 2012 `6191168`,
2013 `6191161`, 2014 `6191162`, 2015 `6191163`, 2017 `6191165`,
**2018 `6191167`** ← берём этот, самый свежий.

Формат — TSV, 71 144 строки, 50 колонок.

## Нужные колонки — все на месте, проверено

```
Restaurant  Item_Name  Food_Category  Serving_Size_household
Calories    Protein    Carbohydrates  Total_Fat
```
Плюс натрий, сахар, клетчатка, транс-жиры — если понадобятся позже.

## Главный риск — свежесть

Данные за 2018 год. Замер дрейфа на двух позициях:

| Позиция | MenuStat 2018 | Сейчас у сети | Дрейф |
|---|---|---|---|
| Big Mac | 540 ккал, Б25 У46 Ж28 | 580 ккал, Б25 У45 Ж34 | ккал +7%, жир +21% |
| Taco Bell Crunchy Taco | 170 ккал, Б8 У13 Ж9 | 170 ккал | совпадает |

Калории дрейфуют умеренно, отдельные макросы заметно.

**Обязательно перед релизом:** сверить топ-20 позиций каждой из восьми
ключевых сетей с их текущими опубликованными данными и поправить вручную.
Это ~160 позиций, работа на день, закрывает большинство реальных запросов.

Оговорка в `description.txt` про то, что порции и рецепты меняются, этот риск
покрывает — но она не заменяет аудит.

## Почему не USDA — разбор ошибки

В первой версии этого документа стояла таблица покрытия по USDA:
Olive Garden 29 909, Panera 20 225, Chick-fil-A 7 696. **Эти числа не значат
того, что я им приписал.**

**1. `totalHits` — это OR по словам запроса, а не число позиций сети.**

| Запрос | totalHits |
|---|---:|
| `Chick-fil-A` | 7 696 |
| `Chick-fil-A Chicken Sandwich` | 26 022 |

Добавление уточняющих слов увеличило число хитов втрое. При AND-семантике это
невозможно. Значит «Olive Garden 29 909» считает записи со словом *olive*
(оливковое масло) и *garden* (garden salad), а не позиции меню сети.

**2. В выдаче нет позиций меню.** Первые результаты по
`Chick-fil-A Chicken Sandwich` — бутилированный соус Chick-fil-A в рознице
(`brandOwner: T. Marzetti Company`, 16 fl oz) и куриный сэндвич от
Foodbrands America. Ни одной позиции меню сети.

**3. Причина системная.** `dataType=Branded` — это Global Branded Food Products
Database, каталог упакованных товаров с UPC-штрихкодом. У блюда в ресторане
UPC нет, поэтому его там принципиально не может быть.

**4. `DEMO_KEY` — 10 запросов в час** (заголовок `x-ratelimit-limit: 10`),
а не 30, как было написано.

Урок: я померил размер выдачи и назвал его покрытием, ни разу не посмотрев,
что в этой выдаче лежит. Проверять надо содержимое, а не счётчик.
