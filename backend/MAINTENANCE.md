# Как база живёт дальше

Стратегия регулярного обновления и поддержки каталога. Не «что сделать
один раз», а как это крутится без человека и где человек всё-таки нужен.

## Что меняется и как часто

Три потока с разной скоростью — и разной ценой ошибки.

| поток | кто меняет | как часто | цена ошибки |
|---|---|---|---|
| цифры этикетки | сеть → подрядчик (Nutritionix) | сеть — раз в квартал; подрядчик — непрерывно | высокая: человек считает по ним |
| присутствие в меню | сеть (сезонные и LTO) | ежемесячно | средняя: снятое блюдо в списке |
| снимки | сеть (новые блюда, редизайн) | редко | низкая: карточка без картинки |

Отсюда каденция: **ядро — 7 дней, хвост — 30**. Это уже записано в
`chains.crawl_every`, а `crawl_queue` уже решает, чья очередь. Никакой
второй очереди заводить не надо.

## Один контур вместо заходов руками

Сегодня `refresh-menus.yml` (понедельник, 06:00 UTC) зовёт
`refresh_chain.py --all`, а тот знает две сети и старый маршрут. Всё, чем
база наполнена, живёт в других скриптах и запускается руками. Контур
замыкается так:

```
crawl_queue → кто сегодня
  └ по chains.source_kind:
      label_provider → adapters/nutritionix   (цифры + свежесть)
      json_api       → адаптер сети           (цифры)
  └ check_menu_presence                       (что сняли с меню)
  └ chain_photos <сеть>                       (снимки: только у кого нет)
  └ relink_photos --apply                     (чужие привязки — прочь)
  └ readiness                                 (кто готов, кто выпал)
  └ publish_pack — если готовых не стало меньше
```

Каждый шаг уже существует и работает поодиночке. Работа — переписать
`refresh_chain.py`, чтобы он брал шаги из `source_kind` и шёл по очереди,
а не по вшитому списку из двух имён.

**Строго по одной сети за раз.** Два скрипта, заводящие временную роль в
Supabase одновременно, роняют её предохранитель на десять минут.

## Где крутить

Раннеры GitHub Actions стоят в США — проверено 2026-09-10 запуском
`probe-sources`: выход US Dulles (Azure), и Akamai его не режет. Оттуда
Taco Bell отдаёт 445 снимков, Applebee's — 161, Olive Garden — 35, а с
машины разработчика без VPN все три отвечают 403 или подсовывают местную
локаль. Self-hosted runner не нужен; VPN на Mac — только для ручной
разведки.

Репозиторий публичный, минуты Actions бесплатны.

**Что контур сейчас держит:** `SUPABASE_ACCESS_TOKEN` в секретах
репозитория отвечает «Your account does not have the necessary
privileges». Токен заводится в дашборде Supabase (Account → Access
Tokens) и кладётся в Settings → Secrets репозитория — оба шага делает
владелец проекта. До этого `refresh-menus` падает на `supabase link`, а
`probe-sources` работает: ему секреты не нужны.

## Что защищает от порчи

Четыре заслона, все уже есть:

1. **`crawls.status = held`** — дифф больше 30 % изменений или 20 %
   пропаж не применяется. Редизайн сайта не затирает каталог.
2. **Порог готовности в сборке пака** — сеть, у которой протухла
   свежесть или пропали снимки, *сама выпадает* из пака. Клиент не видит
   плохих данных; он видит на одну сеть меньше — и это видно в отчёте.
3. **`relink_photos.py`** после любой правки правила сопоставления —
   иначе в базе остаются привязки прежнего, более мягкого правила.
4. **Тесты матчера в `backend-ci.yml`** — каждый пойманный промах
   («Farmhouse» ↔ «Maplehouse», «Whopper» ↔ «Double Whopper») закреплён и
   не вернётся.

Слабое место, о котором надо знать: подрядчик этикетки — **одна точка на
85 сетей**. Сменит разметку — все 85 разом перестанут обновляться. Они не
сломаются (заслон 2), но начнут стареть. Страховка: тест адаптера на
сохранённой странице и сигнал «разобрано ноль строк» как ошибка запуска,
а не тихий пропуск.

## Что видно человеку

Раз в неделю одна таблица — `readiness.py`. Три числа, которые важны:
готовых сетей, кто выпал с прошлой недели, кто добавился. Отчёт писать не
только в лог запуска, а в базу (`readiness_runs`), чтобы видеть динамику,
а не один срез. Падение workflow GitHub присылает письмом сам.

## Что не автоматизируется

Раз в месяц около часа руками:

- **адрес меню новой сети** — понять, национальный это сайт или страница
  франшизы, скрипт не умеет (`crawl_queue` покажет «найти адрес меню»);
- **сломанный адаптер** — сеть переехала на другую платформу;
- **разрешения** — письма сетей хранить рядом с `RIGHTS`, с датой.

## Снимки: как не делать это вечно

Поштучные адаптеры — самая хрупкая часть. Правило: **платформа важнее
сети**. Один адаптер на Sanity закрыл три сети RBI, один на Contentful —
пять сетей GoTo Foods, один на Olo — Chili's и Applebee's. Новую сеть
сначала проверять на платформу (Olo, Contentful, Sanity, AEM, WordPress,
Next.js) и только потом писать своё. Архивная копия сайта — запасной
путь, когда сеть закрылась географией или редизайном.

Порог снимков считается по блюдам; добавки и чужие бутылки его не
держат. Это значит, что «дособрать» сеть до 90 % — конечная работа, а не
бесконечная.

## Приоритеты: не все 96 одинаково

`search_events` пишет, что искали и не нашли. Это и есть очередь: сеть,
которую ищут и не находят, важнее сети, которую никто не открывал.
Ядро (7 дней) — по этой таблице, не по размеру меню.

## Инструменты агента

Всё, что агент делает с базой, — четыре команды. Порядок важен, и
параллельно их не запускать (предохранитель временных ролей в Supabase).

```
probe_photo_sources.py [--apply]     разведка: платформа снимков → chains.photo_probe
refresh_chain.py --due --apply       обход по очереди: цифры → присутствие → снимки
relink_photos.py --apply             после правки правила сопоставления
readiness.py --record                кто готов, срез в readiness_runs
```

То же самое из Actions, без машины разработчика:

```
gh workflow run probe-sources.yml -f chains="sonic arby-s"
gh workflow run refresh-menus.yml -f chains="taco-bell" -f dry_run=true
gh workflow run refresh-menus.yml                      # очередь + публикация auto
```

`--due` берёт только тех, у кого вышел срок (`crawl_every`: ядро 7 дней,
хвост 30). Сразу после большого прогона очередь пуста, и запуск честно
ничего не делает — это не поломка. Чтобы проверить контур, называйте сети
явно.

Подключить сеть на известной платформе = строка в `chains`:
`photo_source_kind` (из `adapters/photo_sources.KINDS`), `photo_source_url`,
`photo_rights`. Код не трогается. Krystal, Hardee's и Carl's Jr подключены
именно так — три `update`.

## Чеклист новой сети

1. `probe_photo_sources.py <slug>` — платформа и сколько снимков видно.
2. Цифры: подрядчик этикетки (`nutritionix.SLUGS`) или свой источник →
   `chains.source_kind`, `source_url`.
3. Снимки: платформа известна → строка в `chains`; нет → адаптер по
   образцу (WordPress — Chick-fil-A, Next.js — Taco Bell, разделы —
   Culver's) и новый вид в `photo_sources.KINDS`.
4. Права: письмо сети в папку с разрешениями, строка в `photo_rights`.
5. `refresh_chain.py <slug> --apply`, потом `readiness.py` — видно, чего
   не хватает до порога.

## Запаркованные сети — и почему

Разведка 2026-09-11 показала, что «по образцу Culver's» — не одна группа,
а тринадцать разных устройств. Шаблонный слой на этом кончился; дальше —
по API каждой сети, и не у всех он открыт.

| сеть | что мешает | что нужно |
|---|---|---|
| Domino's | меню собирают микрофронтенды через `POST /api/web-bff/graphql`; ответ браузер не сохраняет, `fetch` при переходе в раздел не зовётся | перехват ответа BFF или связь продукт → uuid снимка в их CMS (`/cms/assets/<uuid>`). Публичный API заказа (`order.dominos.com/power`) отдаёт 68 продуктов с `ImageCode`, но адрес снимка по коду сменился вместе со сборкой |
| Sonic, Arby's | меню рисует браузер; в разметке только «Top Picks», ссылок на разделы нет | токен доставки Contentful (space `whnlxz6bna9d` у Sonic, `30q5w5l98nbx` у Arby's) — в открытом виде в страницах и чанках не найден |
| Olive Garden, LongHorn, Capital Grille, Yard House, Sheetz | с нью-йоркского VPN — пустая оболочка 2–7 КБ; с раннера GitHub Olive Garden отдаёт 35 снимков | запуск с раннера — после обновления `SUPABASE_ACCESS_TOKEN` |
| Outback, Bonefish, Carrabba's | оболочка 35 КБ, данных в `__NEXT_DATA__` нет | их API меню |
| Pizza Hut | GraphQL `services.digital.pizzahut.com` с публичным ключом в странице | текст запроса меню |
| Baskin-Robbins, Chipotle | AEM, но `.model.json` и опись ассетов закрыты | 14 снимков на странице меню у Baskin-Robbins — мало |
| Sbarro | во всех четырёх разделах те же 13 блюд | больше на сайте нет |

**Выгоднее ломать не закрытые сети, а разрыв у открытых.** У Taco Bell
на сайте 445 снимков при покрытии 32 %, но большая часть «без снимка» —
пиво Cantina, а не блюда; у Applebee's и McAlister's промахи были в
сопоставлении (скобки в имени). Такие правки дают больше снимков на
единицу работы, чем очередной API.
